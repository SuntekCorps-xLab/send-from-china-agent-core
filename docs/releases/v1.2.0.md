# Agent Core v1.2.0 release notes

## Release status and identity

This document describes the `v1.2.0` release candidate. It is not evidence that
the tag or GitHub Release exists. Release identity is generated at release time
from `git rev-parse HEAD` and `git rev-parse HEAD^{tree}`; no future merge SHA is
embedded in this file.

After the exact release commit has passed CI and CodeQL, create the reviewed
`v1.2.0` tag on that same commit. Then generate the immutable evidence manifest
from the independently produced paired E2E artifact:

```bash
npm run release:evidence -- \
  --paired-artifact /path/to/paired-release-evidence.json \
  --ci-url https://github.com/SuntekCorps-xLab/send-from-china-agent-core/actions/runs/RUN_ID \
  --codeql-url https://github.com/SuntekCorps-xLab/send-from-china-agent-core/actions/runs/RUN_ID \
  --sbom-url https://github.com/SuntekCorps-xLab/send-from-china-agent-core/actions/runs/RUN_ID \
  --browser-url https://github.com/SuntekCorps-xLab/send-from-china-agent-core/actions/runs/RUN_ID \
  --security-url https://github.com/SuntekCorps-xLab/send-from-china-agent-core/actions/runs/RUN_ID \
  --output build/release-evidence-v1.2.0.json
```

The input must satisfy
[`paired-release-evidence.v1.schema.json`](../../contracts/paired-release-evidence.v1.schema.json).
The generator rejects a mismatched Agent Core commit or tree, fewer than ten
successful journeys, any failed journey, browser credentials, commerce writes,
or a claimed App Proxy run without `app_proxy_live_verified=true`.

## What is included

- An invite-protected Hosted Sandbox candidate with a synthetic mode and a
  fail-closed, server-side Shopify read-only mode.
- Search Contract v2 across HTTP, MCP, the dependency-free JavaScript SDK, and
  sandbox routes without removing the stable `product_search` v1 adapter.
- A live read-only MCP onboarding path that returns allowlisted public catalog
  fields and links results back to the Shopify product page.
- Tested terminal catalog-miss and sourcing-proof behavior, including tenant
  isolation, 15-minute proof expiry, restart invalidation, idempotency, and
  non-persistence boundaries.
- Correct SDK examples using `results`, structural request equality independent
  of JSON key order, and cross-platform Python runtime discovery for checks.

## Capability boundaries

Anonymous managed access is limited to the documented public read tools.
Self-hosted operators can publish their own allowlisted snapshot. The Shopify
provider is read-only and server-side. Price, publication, and availability are
point-in-time Shopify facts and must be read again before any customer action.

This release does not grant checkout, payment, order, inventory, publication,
product mutation, automatic procurement, or production sourcing authority. The
repository sourcing lifecycle and local catalog are synthetic, illustrative,
non-purchasable fixtures. It does not claim that the Reference Store public App
Proxy has passed a real-store 10/10 journey gate.

## Install, upgrade, and rollback

For a new self-hosted installation, clone the `v1.2.0` tag, run `npm ci`, then
`npm run setup` and `npm run verify`. Existing `1.1.x` installations should
take a snapshot of their deployment configuration and published catalog,
checkout `v1.2.0`, repeat the locked install and verification, and deploy only
the reviewed bundle. Search Contract v2 and the v1 adapter remain compatible.

To roll back, route traffic to the previously verified Worker deployment and
checkout the prior stable tag. Do not reuse a new bundle with old release
metadata. Validate discovery, MCP initialize, `product_search`, pagination, and
product detail again after either upgrade or rollback.

## Required evidence before publishing

- [CI workflow](https://github.com/SuntekCorps-xLab/send-from-china-agent-core/actions/workflows/ci.yml)
  successful on the exact release commit.
- [CodeQL workflow](https://github.com/SuntekCorps-xLab/send-from-china-agent-core/actions/workflows/codeql.yml)
  successful on the exact release commit.
- `spdx-sbom-<commit SHA>` artifact parsed as SPDX 2.3.
- Hosted and local sandbox verification, plus the browser QA artifact, with no
  serious/critical accessibility issue, overflow, console error, or credential
  exposure.
- Public safety scan, dependency audit, Worker verification, SDK tests, Python
  checks, and generated Search Contract types all successful.
- An independently generated, exact-SHA Agent Core and Reference Store paired
  artifact with at least ten successful journeys and zero failed journey,
  browser credential, commerce write, or credential exposure.

The GitHub Release description must link the generated evidence manifest and
the exact workflow runs. A tag, badge, or this candidate document alone is not
release evidence.
